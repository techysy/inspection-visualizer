# 在线状态 CSV 接入

把视频平台导出的「监控点在线状态」CSV（明细或已汇总）导入 Inspection Visualizer，写入区域级巡检记录。

## 支持两种 CSV 格式

### 1. 监控点明细 CSV（一行一个监控点）

```
监控点名称,所在区域,IP地址,在线状态,状态变更时间,状态持续时长,录制状态,巡检时间,国标编码,离线原因,资源编码
10号立杆球机,中江县/东江公园,172.16.101.31,离线,2026-03-10 18:41:20,149天15.79小时,--,2026-08-07 10:28:40,,网络超时或设备无响应,
```

脚本会按**所在区域**自动聚合出：总数 / 在线 / 离线 / 在线率。

### 2. 区域汇总 CSV（一行一个区域）

```
所在区域,监控点总数,在线数,离线数,未检测数,白名单数,在线率
中江县,682,577,105,0,0,84.60%
城管一期,73,67,6,0,0,91.78%
```

脚本**直接透传** CSV 里的数字和在线率，不再二次聚合。

两种格式都会自动识别，不需要额外参数。

## 为什么需要聚合/透传

系统的巡检对象是**区域级**的（中江县、东江公园、城管一期……），指标是「在线 / 在线率」这类聚合数字。

直接把明细 CSV 丢进 `/import` 页面会有三个问题：

| 问题 | 后果 |
|---|---|
| 一行明细 = 一条巡检记录 | 一次导入产生几百条记录，全部挂在同一个区域对象下，趋势图被打爆 |
| 没有数字指标 | `metrics` 为空，趋势图无数据，阈值判定失效 |
| 时间列取错 | 页面按关键词「时间」匹配，会抢到「状态变更时间」而非「巡检时间」，记录散落到几个月前 |

本脚本先聚合再入库，一个区域一天只产生一条记录，且带完整指标。

## 安装

仅依赖 Python 标准库，无需 pip 安装。

```bash
cd integrations/online_status_csv
cp .env.example .env
# 编辑 .env，填入 IV_URL 和密码
```

密码填项目根目录 `.env` 里的 `APP_PASSWORD`，或某个巡检人员的 `username` + `password`。

**默认「仅匹配已有区域」**：`匹配对象` 列显示会命中哪个已有巡检对象；CSV 中那些 IV 里没有对应区域的行会被直接跳过（末尾 `跳过(无匹配)` 列出），不会自动新建对象。确认 `匹配` 数符合预期、被跳过的都是确实不需要的区域后，再去掉 `--dry-run`。

> 如果确实需要为缺失区域自动新建巡检对象，加 `--allow-create`（详情见参数表）。

### 正式导入

```bash
python csv_to_iv.py -f 在线状态_20260807.csv
```

## 参数

| 参数 | 说明 |
|---|---|
| `-f, --csv` | CSV 文件路径（必填） |
| `--dry-run` | 只预览聚合结果，不写库 |
| `--area-mode` | 仅对**明细 CSV** 有效：聚合粒度，见下表，默认 `leaf` |
| `--timestamp` | 覆盖巡检时间，格式 `YYYY-MM-DD HH:MM` |
| `--min-total` | 区域设备数低于该值则跳过，默认 1 |
| `--allow-create` | 为 CSV 中 IV 没有对应区域的行自动新建巡检对象（默认**关闭**，仅匹配已有区域，未匹配区域跳过） |
| `--inspector` | 巡检人名称 |
| `--iv-url` / `--username` / `--password` | 覆盖 `.env` 配置 |

### 聚合粒度

区域字段 `中江县/东江公园` 是层级路径，用 `--area-mode` 控制拆到哪一级：

| 模式 | 结果 | 适用场景 |
|---|---|---|
| `leaf` | 东江公园 | 默认，各子区域独立看趋势 |
| `root` | 中江县 | 只关心全县总在线率 |
| `full` | 中江县/东江公园 | 系统里对象位置就是完整路径 |
| `both` | 东江公园 + 中江县 | 子区域和全县汇总都要，各写一条 |

## 写入格式

聚合结果拼成后端认得的 `status_detail`，走现有 `/api/records/import`，**不需要改后端代码**：

```
监控点总数: 40; 在线: 34; 离线: 6; 在线率: 85.00%
```

后端 `_parse_status_to_metrics` 会解析成：

```json
{"监控点总数": "40", "在线": "34", "离线": "6", "在线率": "85.00%"}
```

离线设备名和原因写入 `notes` 字段，例如：

```
离线: 1号立杆球机、2号立杆球机、3号立杆球机 等 6 台；原因: 网络超时或设备无响应×6
```

巡检结果由脚本初判（在线率 <90 异常 / <100 需关注 / 其余正常），若对象配置了指标阈值，后端 `_check_metrics_thresholds` 会覆盖为按阈值判定的结果。

## 注意事项

- **明细 CSV 必须是全量导出**（在线 + 离线都有）。如果平台只导出离线设备，脚本会警告 `CSV 中没有任何「在线」行`，此时在线率算出来是 0%，数据不可用。
- 明细 CSV 按「所在区域」聚合，未填区域的行会归入「未分配区域」并给出警告。
- **默认只写已存在的区域**：CSV 中 IV 没有对应巡检对象的区域会被跳过（dry-run 会明确列出），需要新建对象时显式加 `--allow-create`。
- **自动应用全局位置别名**：导入前会读取 `global_vars.json` 里的 `location_aliases`（若已登录则优先从 `/api/global-vars` 拉取）。例如 CSV 里写「中江县综合行政执法局」会自动映射到「城区」并命中已有对象；汇总 CSV 里的「三期垃圾压缩站」也会自动映射到「垃圾压缩站」。
- 表头列名做了别名兼容（如「区域」「所属区域」「组织」「总数」「在线数」「在线率」等都能识别）。
- 分隔符自动探测，支持逗号 `,`、制表符 `\t`、分号 `;`。
- 编码自动探测 `utf-8-sig / utf-8 / gbk / gb18030`。
- **汇总 CSV 直接透传数字和在线率**，不再二次聚合；`--area-mode` 对汇总表无效。

## 定时执行

Windows 任务计划程序：

```
程序:  C:\path\to\inspection-visualizer\venv\Scripts\python.exe
参数:  csv_to_iv.py -f D:\exports\latest.csv
起始于: C:\path\to\inspection-visualizer\integrations\online_status_csv
```

Linux crontab（每天 9 点）：

```bash
0 9 * * * cd /opt/inspection-visualizer/integrations/online_status_csv && ../../venv/bin/python csv_to_iv.py -f /data/exports/latest.csv >> /var/log/csv_to_iv.log 2>&1
```
