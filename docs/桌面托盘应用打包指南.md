# 桌面托盘应用打包指南(Electron 壳 + Python sidecar + npm CLI)

> 从 `inspection-visualizer` 项目沉淀,适用于任何「Web 服务 + 托盘管理」项目(参考实现:[inspection-visualizer](https://github.com/techysy/inspection-visualizer) 的 `desktop/` 与 `cli/` 目录)。
> 阅读对象:想把一个 Flask / Node / 任意 HTTP 服务封装成"装完即用、托盘管理"桌面产品的开发者。

---

## 1. 三种发行形态怎么选

| 形态 | 目标人群 | 托盘 | 运行时 | 本仓库参考 |
|---|---|---|---|---|
| **A. Electron 桌面版**(NSIS 安装包 / 便携 exe) | 非技术用户 | Electron Tray + 内嵌窗口 | **内嵌** Windows Embeddable Python,免装环境 | `desktop/` |
| **B. npm CLI**(`npm i -g`,命令 + 托盘) | 开发者/极客 | Win=PowerShell NotifyIcon;mac/Linux=systray2 | 系统 Python,首启自动建 venv | `cli/` |
| **C. 无桌面环境(NAS/服务器)** | — | ❌ 无托盘概念,浏览器访问即可 | Docker / 系统 Python | —(如需可自行加 Dockerfile) |

> 经验:托盘是"桌面"概念。NAS/服务器场景不要硬塞托盘,Web UI 就是唯一界面。

## 2. 架构与职责

```
┌─ Electron main(main.js)──────────────┐      ┌─ Python sidecar ────────────┐
│ 托盘图标/菜单 · BrowserWindow         │ spawn│ app.py → waitress 0.0.0.0:P │
│ 单实例锁 · 健康轮询 /api/health       │ ───→ │ IV_ELECTRON=1 IV_PORT=...   │
│ 开机自启(setLoginItemSettings)       │      │ IV_DATA_DIR=<userData>      │
└──────────────────────────────────────┘      └─────────────────────────────┘
        │ 1.2s 轮询 /api/health(免鉴权)             │ 数据全部写 IV_DATA_DIR:
        └───────────────────────────────────────────┘ db / *.json / backup / log
```

**状态机**:`stopped → starting →(health ok)→ running`;端口被占且健康 → `external`(直接开窗,不杀别人的服务);python 退出 → `stopped` + 气泡提示。

**生命周期规则**:

| 动作 | 行为 |
|---|---|
| 启动应用 | 托盘 + spawn python(先 health 预检)→ 就绪后自动开窗 |
| 关闭窗口 | `preventDefault` + `hide()` —— 缩到托盘,不退出 |
| 停止服务(菜单/CLI) | 只杀 python 进程树,壳常驻 |
| 退出(菜单/`iv quit`) | 停服务 → 杀托盘 → 进程退出 |
| 开机自启 | 登录时拉起托盘壳(壳再拉起服务) |

## 3. Web 服务侧改造清单(4 项)

这 4 项让服务"可被壳管理",**不破坏原有命令行启动方式**(所有行为由环境变量开关):

1. **数据目录注入**(`config.py`):`IV_DATA_DIR` 存在时,db / json 配置 / 日志 / 备份全部落到该目录(不存在则启动时 `mkdir -p`);未设置时保持原布局。参考实现:

   ```python
   IV_DATA_DIR = os.environ.get('IV_DATA_DIR')
   DATA_DIR = Path(IV_DATA_DIR) if IV_DATA_DIR else MODULE_DIR
   if IV_DATA_DIR:
       DATA_DIR.mkdir(parents=True, exist_ok=True)   # SQLite 不会自建父目录!

   def data_file(filename):   # 桌面版模式:缺省配置从程序目录复制到数据目录
   def data_subdir(name):     # 桌面版模式:自动 mkdir
   ```

2. **生产服务器**(`app.py`):`IV_ELECTRON=1` 时用 `waitress.serve(host=IV_HOST, port=IV_PORT)`,否则走原开发模式。`requirements.txt` 加 `waitress`。

3. **健康检查**:加免鉴权路由(记得加进鉴权白名单):

   ```python
   @main.route('/api/health')
   def api_health():
       return jsonify({'status': 'ok'})
   ```

4. **初始凭证落盘**:随机生成的初始密码/密钥没控制台可打印时,写到数据目录文件,壳读文件做气泡提示(详见 `config.py::_resolve_app_password` 与 `main.js::maybeNotifyPassword`)。

## 4. Electron 壳(`desktop/`)

```
desktop/
├── main.js                    # 全部壳逻辑(约 300 行,零 npm 运行时依赖)
├── package.json               # electron + electron-builder(devDeps)+ build 配置
├── icon.ico / icon.png        # 托盘/安装包图标
├── make_icon.py               # 用 Pillow 生成图标(可换成自己的)
├── build-python-runtime.ps1   # 构建 Windows Embeddable Python 运行时
├── build.ps1                  # 一键打包(源码汇集 → electron-builder)
└── create-shortcut.ps1        # 便携版手动建桌面快捷方式
```

`main.js` 的 10 个关键点(照抄即可):

1. `app.requestSingleInstanceLock()` 单实例;二次启动 → `second-instance` 事件里开窗。
2. spawn 用 **`pythonw.exe`**(无控制台闪烁)+ `windowsHide: true`;开发模式回退仓库 venv,支持 `IV_PYTHON` 覆盖。
3. 注入环境变量:`IV_ELECTRON=1 / IV_HOST=0.0.0.0 / IV_PORT / IV_DATA_DIR=app.getPath('userData') / PYTHONUNBUFFERED=1`。
4. 健康轮询 `http.get /api/health` 每 1.2s,90s 超时;期间进程退出则中止等待。
5. 停止 = `taskkill /PID <pid> /T /F` 杀整棵树;**status 非零时用 `wmic process where processid=... delete` 兜底**(taskkill 偶发拒绝访问)。
6. 窗口:`show:false` + `ready-to-show` 再 show;`setWindowOpenHandler` 把外链交给系统浏览器;`close` 事件 `preventDefault + hide()`(缩托盘);`will-navigate` 拦截跨站跳转。
7. 开机自启:`app.setLoginItemSettings({ openAtLogin })`,菜单做成 checkbox,**仅打包版启用**(开发模式注册的是 electron.exe,无意义)。
8. 日志:python stdout/stderr 重定向到 `<userData>/logs/server.log`(超 5MB 截断),壳自身事件写 `tray.log`。
9. 托盘菜单随状态机重建(`tray.setContextMenu(rebuild())`),状态行 + 启动/停止/重启按可用性置灰。
10. `will-quit` 时杀 python 进程树,保证退出不残留。

`package.json` 的 `build`(electron-builder)要点:

- `files` 只放壳自己的文件 —— **图标必须显式列出**(`icon.ico`、`icon.png`),否则打进 asar 后托盘拿到空图标,肉眼看不见(踩坑 #1 的变体);
- `extraResources`: `{from: build/app, to: app}` + `{from: build/python, to: python}`,运行时通过 `process.resourcesPath` 定位;
- `win.target = [nsis, portable]`;`nsis.createDesktopShortcut/createStartMenuShortcut: true`(安装即有桌面/开始菜单图标);`mac.target=[dmg]`(x64+arm64);`linux.target=[AppImage, deb]`。

## 5. 打包流水线(Windows 一条龙)

```powershell
cd desktop
.\build.ps1 -Proxy http://<代理>:<端口>   # 全自动,产物在 dist\
```

`build.ps1` 四步:①`build-python-runtime.ps1`(已存在则跳过)→ ②robocopy 汇集服务源码到 `build\app`(排除 venv/日志/备份/.env/*.db)→ ③`npm install`(electron 走 npmmirror)→ ④`npx electron-builder --win`。

**build-python-runtime.ps1 原理**(让 Python 变成"拷走就能跑"的目录):

1. 下载 [Embeddable Python](https://www.python.org/downloads/windows/) zip 解压到 `build\python`;
2. `._pth` 取消 `import site` 注释(**否则 pip 装的包不可导入**),并追加 `..\app` —— **`._pth` 模式不会把脚本目录加进 `sys.path`**,必须手动加,且 `..\app` 相对写法在打包前后布局一致;
3. `get-pip.py` 装 pip → `pip install -r requirements.txt`;
4. 自检 `import flask, waitress, rapidocr_onnxruntime...`。

安装包支持静默装:`InspectionVisualizer Setup x.x.x.exe /S`(NSIS)。便携版用户用 `create-shortcut.ps1` 建桌面快捷方式。

## 6. macOS / Linux 构建

- 配置已就绪(`build.mac` / `build.linux`),但 **mac 构建必须在 macOS 上执行**(`npx electron-builder --mac`,产出 dmg;x64+arm64;`icon.png` 自动转 icns;无开发者证书时 ad-hoc 签名可运行,首次需右键打开);
- Linux 同理 `--linux`(AppImage/deb);
- 没有 mac/Linux 机器时,**形态 B(npm CLI)天然跨三平台**,是最低成本的分发方式。

## 7. npm CLI 形态(`cli/`)

```
cli/
├── cli.js                  # bin 入口:iv(后台托盘)/start/stop/restart/status/open/quit/autostart
├── package.json            # bin 两个字段;files 含 app/(构建产物);prepublishOnly 自动构建
├── src/server.js           # Python 探测(IV_PYTHON_CMD > py -3 > python)· venv 供给 · 启停 · 健康
├── src/tray/               # 托盘与自启(跨平台)
├── hooks/postinstall.js    # 只做环境检查提示,绝不阻塞安装(package.json comment_* 字段写明原因)
└── scripts/build-cli.js    # 把服务源码汇集到 cli/app/
```

关键设计:

- **托盘跨平台**:Windows 用 **PowerShell NotifyIcon**(`trayWin.js` + `tray.ps1`,stdin/stdout 走 JSON 协议,零二进制依赖、杀软友好);mac/Linux 用 `systray2`,发布包**不带** Go 二进制,postinstall 惰性装到 `~/<app>/runtime/node_modules`(避免杀软误报);
- **运行时供给 `ensureRuntime`**:venv 建在 `~/<app>/runtime/venv`,以 `requirements.txt` 哈希做标记文件,变了才重装;支持 `--proxy` 与 `IV_PYTHON_CMD`;失败信息里直接给出下一步命令;
- **托盘后台常驻**:`iv` 只负责把 `node cli.js --tray` spawn 成 detached 进程后立即返回(关终端不影响);worker 用**退出标记文件**(`tray.quit`)实现 `iv quit` 的优雅收尾(杀进程收不掉 PowerShell 托盘子进程);pid 文件的**写入职责只在 worker**,launcher 只读——否则会产生"launcher 把自己写进 pid 文件 → worker 误判已有实例而自杀"的竞态;
- **自启三平台**:`autostart.js` —— Windows 启动文件夹 VBS(隐藏窗口)、macOS launchd plist、Linux XDG desktop entry;
- 数据目录与桌面版**保持一致**(如 `%APPDATA%\InspectionVisualizer`),同一端口健康预检,两种形态互斥运行。

## 9. 踩坑实录(现象 → 原因 → 解法)

1. **打包装置里托盘图标"看不见"**:asar 里没有图标文件(`files` 没列)→ `nativeImage` 为空 → Tray 对象存在但图标空白。→ `files` 显式加 `icon.ico/icon.png`,`npx asar list` 验证。
2. **打包后 `ModuleNotFoundError: app_factory`**:Embeddable Python 的 `._pth` 模式**不把脚本目录加进 sys.path**。→ `._pth` 追加 `..\app`(相对 python 目录,打包/安装后布局一致)。
3. **.ps1 中文脚本报"字符串缺少终止符"**:PowerShell 5.1 把无 BOM 的 UTF-8 当 ANSI 读。→ 存成 **UTF-8 with BOM**。
4. **electron-builder 卡死在 winCodeSign 解压**:包里两个 macOS dylib 符号链接,Windows 无特权解不开。→ 手动把 winCodeSign-2.6.0.7z 解压到 `%LOCALAPPDATA%\electron-builder\Cache\winCodeSign\winCodeSign-2.6.0\`(忽略那两个 symlink 报错),rcedit 等其余文件完好即可。
5. **npm 11 提示 install-scripts 未允许**:electron 的 postinstall、自家 postinstall 都可能被拦。→ `npm install-scripts approve electron`;自家 postinstall 设计成非致命(`|| exit 0`),被拦也不影响功能。
6. **首次启动弹 Windows 防火墙**:绑定 `0.0.0.0` 必然触发,**每个新 python.exe 路径弹一次**(开发 venv 和打包运行时是两个路径);安装版路径固定,只弹一次,点允许(专用网络)即可。
7. **`taskkill` 偶发"拒绝访问"**:对 detached 的 pythonw 可能发生。→ WMI 兜底(`wmic process where processid=N delete`),且**必须复查端口/进程确认真的死了**,否则会误报已停止。
8. **SQLite `unable to open database file`**:IV_DATA_DIR 目录不存在,SQLite 不建父目录。→ 模块加载时 `mkdir(parents=True, exist_ok=True)`。
9. **服务"已在运行"检测**:先 `GET /api/health`,通 → external 模式直接开窗,绝不再 spawn 第二个实例(避免双实例抢端口)。
10. **关终端把托盘带走了**:托盘跑在前台 shell 里。→ detached worker + 退出标记文件(见 §7)。

## 10. 发布清单

- **npm CLI**:`cli/package.json` 改版本 → `npm publish --registry https://registry.npmjs.org --access public`(`prepublishOnly` 自动构建);发布前停掉以 `cli/app` 为 cwd 的服务进程,否则 Windows 上目录被锁、构建失败;
- **Electron**:`desktop/package.json` 改版本 → `build.ps1` → 产物在 `desktop/dist\`;
- npm 官方源发布后,npmmirror 同步有延迟(几分钟到更久),可到 `https://npmmirror.com/sync/@scope/pkg` 手动触发;
- 三处版本号同步:`cli/package.json`、`desktop/package.json`、`ChangeLog.md`。
